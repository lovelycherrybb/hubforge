# 产品需求文档(PRD) — HubForge

> **产品名称**: HubForge — Vibecoding 统一应用门户框架
> **版本**: V1.0
> **撰写人**: 设计师（AI）
> **撰写日期**: 2026-07-23
> **状态**: 评审中

---

## 1. 概述

### 1.1 背景

vibecoding（AI辅助编程）浪潮下，传统企业业务人员能用 Cursor/Claude Code 等工具快速产出应用。但这些应用碎片化严重——各自独立部署、各自一套用户系统、没有统一入口。企业需要一个"应用容器"来统一管理这些 vibecoding 产出。

### 1.2 目标

| 目标类型 | 目标描述 | 衡量标准 |
|----------|----------|----------|
| 业务目标 | 建立 vibecoding 应用的统一管理平台 | 所有 vibecoding 应用通过 HubForge 统一入口访问 |
| 用户目标 | 业务人员 30 分钟内完成应用接入 | 按文档操作即可，不改应用代码 |
| 技术目标 | 支持 PC 网页应用和 H5 应用双端接入 | 两种类型应用均可独立运行和嵌入运行 |

### 1.3 范围

**V1.0 包含:**
- 多租户管理（租户创建、配置、数据隔离）
- 统一用户/组织管理（注册、登录、组织架构 CRUD）
- 两层权限体系（框架权限 + 应用权限）
- 应用管理（应用注册、配置、iframe 嵌入）
- PC Web 端门户（桌面浏览器完整访问）
- H5 移动端门户（手机浏览器核心功能访问）
- 应用开发规范 + 脚手架模板（create-hubforge-app）
- 应用双模运行支持（standalone 独立运行 / embedded 嵌入运行）

**V1.0 不包含:**
- 移动端原生 App（仅 Web）
- 应用市场/商店（应用审核、评分、付费）
- 消息中心/通知系统
- 数据看板/报表
- 第三方 SSO 对接（如企业微信、钉钉登录）
- 应用间数据互通

### 3.2 功能详情

#### M1: 用户与认证

**功能描述**: 统一的用户注册、登录、登出系统，基于 JWT 认证。

**功能流程**:
1. 用户访问 HubForge 域名 → 未登录则跳转登录页
2. 输入邮箱+密码 → 后端验证 → 签发 JWT token
3. 前端存储 token → 后续请求携带 token
4. token 过期 → 自动刷新或跳转登录

**验收标准**:
- [ ] 支持邮箱+密码注册和登录
- [ ] JWT token 有效期 24 小时，支持自动刷新
- [ ] 登出后 token 失效
- [ ] 错误密码 5 次后锁定 15 分钟

#### M2: 多租户

**功能描述**: 支持多个租户（组织/部门），每个租户有独立的用户池和数据域。主租户拥有全局管控能力。

**主租户管理后台（主租户专属）**:

主租户管理员登录后，看到"全局管理"入口，包含：

| 管理功能 | 说明 | 优先级 |
|----------|------|--------|
| 租户总览 | 所有租户列表、状态、用户数、应用数 | P0 |
| 租户创建 | 创建新租户，填写名称、配额、管理员 | P0 |
| 租户配置 | 修改租户基础信息、功能开关、配额限制 | P0 |
| 租户停用/启用 | 临时冻结或恢复某个租户 | P1 |
| 全局应用管理 | 查看所有租户的应用接入情况 | P1 |
| 全局用户统计 | 各租户用户数量、活跃度概览 | P2 |

**普通租户管理后台（租户管理员专属）**:

租户管理员登录后，只能管理本租户范围内的内容。

**功能流程**:
1. 主租户管理员创建新租户 → 填写租户名称、配额、指定租户管理员
2. 租户管理员收到账号 → 登录 → 只能看到本租户的用户、组织、应用
3. 数据访问通过中间件自动注入租户 ID 过滤

**验收标准**:
- [ ] 主租户可创建/编辑/删除/停用租户
- [ ] 主租户可查看所有租户的用户数、应用数等统计
- [ ] 主租户可配置每个租户的功能开关和配额
- [ ] 租户之间数据完全隔离
- [ ] 租户管理员只能看到本租户数据
- [ ] PostgreSQL RLS 策略生效

#### M3: 组织架构管理

**功能描述**: 每个租户拥有独立的组织架构（部门树），用于管理本租户下的用户归属和权限继承。

**组织架构模型**:

```
租户A
├── 总公司
│   ├── 生产部
│   │   ├── 一车间
│   │   └── 二车间
│   ├── 质检部
│   └── IT部
└── 分公司
    ├── 销售部
    └── 售后部
```

**功能清单**:

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 部门树 CRUD | 创建/编辑/删除/移动组织节点 | P0 |
| 部门下用户管理 | 将用户分配到部门、调整归属、批量导入 | P0 |
| 组织架构树形展示 | PC 端左侧树形 + 右侧详情；H5 端可折叠列表 | P0 |
| 组织级权限继承 | 给某个部门配置权限，该部门下所有用户自动继承 | P1 |
| 组织架构搜索 | 按部门名称/用户名搜索 | P1 |

**功能流程**:
1. 租户管理员进入"组织架构"页面
2. 左侧看到部门树形结构，右侧看到当前选中部门的详情（成员列表）
3. 可以新增子部门、编辑部门名称、删除空部门
4. 可以给部门添加/移除用户
5. 可以给部门配置权限（该部门下用户自动继承）

**验收标准**:
- [ ] 支持多层级部门树（至少 5 层）
- [ ] 部门 CRUD 操作正常（含移动节点）
- [ ] 用户可分配到部门，一个用户只属于一个部门
- [ ] 组织级权限继承生效（给部门配权限 → 下属用户自动获得）
- [ ] PC 和 H5 端均可操作组织架构

#### M4: 权限体系

**功能描述**: 两层权限——框架权限由主租户控制，应用权限由各租户自治。

**权限模型**:

```
框架权限（主租户控制）
├── tenant.admin    — 租户管理员
├── app.[appKey].access — 访问某个应用
└── app.[appKey].admin  — 管理某个应用

应用权限（租户自治）
├── app.[appKey].[permKey] — 应用内自定义权限
└── 由应用在 hubforge.config.json 中声明
```

**验收标准**:
- [ ] 主租户可分配框架权限给任何用户
- [ ] 租户管理员可分配应用权限给本租户用户
- [ ] 应用通过 hubforge.config.json 声明所需权限
- [ ] 权限校验在框架层统一执行

#### M5: 应用管理与门户

**功能描述**: 注册 vibecoding 应用到 HubForge，通过 iframe 嵌入运行。同时提供 PC 和 H5 两种门户界面。

**支持的应用类型**:
- **PC 网页应用**: 桌面浏览器访问的管理后台、数据看板、工作台等
- **H5 应用**: 手机浏览器访问的移动工具、表单填报、现场巡检等

**功能流程**:
1. 业务人员用 vibecoding 工具开发应用（遵循 HubForge 开发规范）
2. 应用独立部署到一个 URL（可本地、可服务器）
3. 在 HubForge 后台注册应用 → 填写应用名称、URL、类型（PC/H5/双端）
4. 配置权限声明 → 应用出现在对应用户的门户中
5. 用户点击应用 → iframe 加载应用 URL

**验收标准**:
- [ ] 支持注册 PC 网页应用和 H5 应用
- [ ] 应用在 iframe 中正常加载和运行
- [ ] 应用 URL 可配置（支持本地开发地址和生产地址）
- [ ] 应用类型标记（PC/H5/双端），门户根据端类型展示

#### M6: 应用开发规范（开发支撑）

**功能描述**: 定义 vibecoding 应用接入 HubForge 的标准，提供脚手架工具。

**hubforge.config.json 规范**:

```json
{
  "name": "设备巡检系统",
  "version": "1.0.0",
  "description": "车间设备日常巡检工具",
  "icon": "/icon.png",
  "type": "h5",
  "entry": "/src/index.tsx",
  "routes": [
    { "path": "/", "title": "巡检首页" },
    { "path": "/record", "title": "巡检记录" },
    { "path": "/report", "title": "巡检报告" }
  ],
  "permissions": [
    { "key": "inspection.view", "label": "查看巡检", "type": "framework" },
    { "key": "inspection.submit", "label": "提交巡检", "type": "app" },
    { "key": "inspection.approve", "label": "审批巡检", "type": "app" }
  ],
  "standalone": {
    "port": 3001,
    "auth": "local"
  }
}
```

**字段说明**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | string | ✅ | 应用名称 |
| type | "pc" / "h5" / "both" | ✅ | 应用类型 |
| entry | string | ✅ | 入口文件路径 |
| routes | array | ✅ | 应用内路由列表 |
| permissions | array | ✅ | 权限声明 |
| permissions[].type | "framework" / "app" | ✅ | framework=框架权限(主租户控), app=应用权限(租户控) |
| standalone.port | number | ✅ | 独立运行端口 |
| standalone.auth | "local" / "hubforge" | ✅ | 独立模式认证方式 |

**双模运行规范**:

应用入口文件必须检测宿主环境：

```typescript
// src/index.tsx
if ((window as any).__POWERED_BY_HUBFORGE__) {
  // 嵌入模式：导出生命周期钩子
  export async function bootstrap() { /* 初始化 */ }
  export async function mount(props: any) { /* 渲染到 props.container */ }
  export async function unmount() { /* 清理 */ }
} else {
  // 独立模式：直接渲染
  const root = createRoot(document.getElementById('root')!);
  root.render(<App />);
}
```

**验收标准**:
- [ ] hubforge.config.json 规范文档完整
- [ ] create-hubforge-app 脚手架可生成 React/Next.js 模板
- [ ] 脚手架生成的应用可独立运行（npm run dev）
- [ ] 脚手架生成的应用可嵌入 HubForge（qiankun 加载）

### 4.2 核心流程

**流程1: 应用接入流程**

```
业务人员用vibecoding开发应用
        ↓

        ↓

        ↓
独立运行测试（npm run dev）
        ↓
部署应用到服务器
        ↓
在HubForge后台注册应用
        ↓

        ↓

```

```
用户打开HubForge域名
        ↓

        ↓

        ↓
点击目标应用
        ↓
iframe加载应用（自动携带认证信息）
        ↓
在应用内操作 ✅
```

## 5. 非功能需求

### 5.1 性能需求
- 页面加载时间: < 2 秒（首屏）
- API 响应时间: < 500ms
- iframe 应用加载: 取决于应用本身，框架侧 < 100ms

### 5.2 安全需求
- 认证: JWT token，有效期 24h
- 密码: bcrypt 加密存储
- 权限: 框架层统一校验，应用层二次校验
- 数据隔离: PostgreSQL RLS + 中间件强制租户过滤
- CSRF/XSS: 标准 Web 安全防护

### 5.3 兼容性需求
- PC: Chrome 90+, Edge 90+, Safari 15+
- H5: iOS Safari 15+, Android Chrome 90+
- 分辨率: PC 1280px+ / H5 375px+

## 9. 风险与依赖

### 8.1 风险

| 风险 | 影响 | 可能性 | 应对措施 |
|------|------|--------|----------|
| qiankun 对 Next.js SSR 支持有限 | 子应用需用 CSR | 中 | HubForge 门户壳用 SSR，子应用统一 CSR |
| iframe 嵌入弹窗/滚动问题 | 用户体验下降 | 中 | 同域部署 + CSS 重置 + 容器样式约束 |
| 应用开发规范太复杂 | 业务人员接入困难 | 中 | 脚手架模板 + Cursor Rules + 示例应用 |
| 多租户数据泄露 | 安全事故 | 低 | RLS + 中间件 + 安全审计 |

### 8.2 依赖

| 依赖项 | 说明 | 状态 |
|--------|------|------|
| 云服务器 | 2C4G 起步 | 需获取 |
| 域名 | hubforge.cn 或其他 | 需获取 |
